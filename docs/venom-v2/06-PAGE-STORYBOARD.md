# VENOM V2 — PAGE STORYBOARD 0.1

This document defines the page before implementation. Each scene must justify its existence.

## Global rule

The page is one continuous organism. The serpent is allowed to connect scenes, but each scene must still work as semantic HTML without the canvas.

---

## SCENE 00 — SIGNAL

Purpose:
Establish control, not spectacle.

Visual:
Near-black screen. Minimal technical signal. VENOM mark / wordmark resolves with restraint.

Motion:
Short system wake-up. No long splash screen. No mandatory wait.

Serpent:
Not visible. At most a moving specular trace.

Copy:
Minimal. No paragraph.

Exit:
The environment opens rather than hard-cuts.

---

## SCENE 01 — EMERGENCE / HERO

Purpose:
Create the unforgettable brand moment and state what VENOM does.

Composition:
Large VENOM/statement on DOM layer.
Fixed 3D canvas behind and between text depth planes.

Serpent:
Macro body segment first.
User initially reads it as material/architecture.
Scroll reveals that it is alive.

Motion:
Camera pullback + serpent spline motion.
Body crosses typography depth.
Head stays hidden.

Interaction:
Pointer influence is subtle, never game-like.

CTA:
One primary project CTA.
One SNAKE entry.

Mobile:
Static/key-art first; simplified real-time layer only if capability allows.

---

## SCENE 02 — THESIS

Purpose:
Explain why VENOM exists.

Visual language:
Obys-like scale discipline without copying composition.
Large statement, extreme spacing, very little media.

Proposed narrative:
Strategy.
Design.
Technology.
Intelligence.
Execution.

Motion:
Typography masks and depth transition only.

Serpent:
Absent. Silence creates contrast.

---

## SCENE 03 — CAPABILITIES

Purpose:
Explain what we build without six generic cards.

Structure:
Numbered chapters / bands.

01 Digital Experiences
02 Websites & Commerce
03 Systems & Products
04 AI & Automation
05 Identity & Creative
06 Performance & Evolution

Visual:
Each capability owns one large compositional state.
Technical index stays stable.

Motion:
CoMinVi-inspired chapter progression:
one capability takes the stage while the previous one recedes.

Serpent:
Body may cross once between two chapters, never once per item.

---

## SCENE 04 — WORK / PROOF

Purpose:
Show evidence.

Structure:
Large case chapters, not portfolio thumbnails.

Each case:
number / client / problem / intervention / outcome / stack / hero media.

Motion:
Stacked transitions, controlled media scale, captions pinned briefly.

Serpent:
No required appearance. Work must be able to dominate.

---

## SCENE 05 — SYSTEMS / SNAKE

Purpose:
Reveal the intelligence layer.

Narrative transformation:
physical serpent -> scale fragments -> particles/data -> interface.

This is the one place where the identity metaphor becomes product logic.

Visual:
Technical grid becomes clearer.
Lime signal becomes more active.

SNAKE:
Native full-width / scene-based interface.
Do not present as a generic floating chat bubble.

Motion:
Particle dissolve is scene-bound.
No permanent rain of particles.

---

## SCENE 06 — HOW WE OPERATE

Purpose:
Explain process and reduce perceived risk.

Sequence:
Understand -> Design -> Build -> Integrate -> Audit -> Evolve

Visual:
A controlled depth/tunnel sequence can work here, but information remains DOM.

Motion:
Camera progression or layered planes.
No endless horizontal carousel.

Serpent:
Could be represented only as a path/line/signal, not literal body.

---

## SCENE 07 — VENOM OS / INTERNAL PROOF

Purpose:
Show that the agency builds its own systems and uses its own method.

Visual:
Real interface evidence from VENOM OS, curated and simplified.

Message:
We build before we promise.

Motion:
Minimal. Product proof gets visual priority.

---

## SCENE 08 — CONTACT / FINAL STRIKE

Purpose:
Conversion + final identity closure.

Visual:
Return to darkness.

Serpent:
First controlled head reveal.
Stillness > attack.
Possible small head/eye acknowledgement when CTA receives pointer/focus.

Copy:
One strong statement.
One CTA.
Direct contact route.

End:
VENOM wordmark.
No visual clutter.

---

## Persistent elements

Header:
minimal, transparent until necessary; becomes legible on scroll.

Scene index:
optional desktop-only technical index.

Cursor:
desktop enhancement only.

SNAKE access:
available after hero but visually integrated; does not compete with page content.

## Content density rule

Every scene gets:
- one job;
- one primary statement;
- one primary interaction;
- one dominant visual mechanism.

If a scene needs three different spectacle effects, redesign it.
